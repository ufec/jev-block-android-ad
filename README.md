# JevNoiseGate

Android 短信与通知降噪应用。消息在设备上由 Laya Multilingual LiteRT 模型分类，再按用户设置的动作与置信度门槛处理。联网仅用于下载模型，不使用 API Key 或云端判断，不上传短信或通知内容。下载支持系统网络、直连和手动代理。

性能与行为细节见 [review](docs/PROJECT_REVIEW.md)、[fixes and validation](docs/FIXES.md)、[performance review](docs/PERFORMANCE_REVIEW.md)、[implemented fixes](docs/PERFORMANCE_FIXES.md)、[second-round review](docs/PERFORMANCE_REVIEW_ROUND2.md) 与 [second-round fixes](docs/PERFORMANCE_FIXES_ROUND2.md)。注意这些文档写于云端后端时期，凡涉及 API Key、`TypeSafeBackend`、代理探测（`ProxyProbe`）的描述已不适用于当前构建。

## 设计原则

### Fail open

所有不确定路径一律落到放行：模型超时、排队超时、模型异常、模型返回答案空间之外的类别。落地点只有 `DecisionMapper` 一处，任何调用路径都无法绕过。

理由：漏放一条广告只是一瞬间的烦扰，错拦一条验证码可能让人被锁在账户外面。这个不对称性大到默认必须偏向放行。

### 本机判定优先于模型

三种情况根本不进模型：

| 机制 | 行为 |
|---|---|
| OTP 闸门 | 识别出验证码格式即放行 |
| 用户纠错 | 恢复过的相同内容与来源桶今后优先放行 |
| 短信号码黑名单 | 命中即静默拦截 |

模型擅长回答"这是不是广告"，不擅长回答"这个号码在我的名单上"。

### 硬规则留在本机

号码黑名单是用户明确填写的精确标识，没有需要权衡的余地；让它依赖模型或缓存状态反而是错的。

## 运行方式

需要 JDK 17 和 Android SDK 37。模型不进入 APK，也不提交到仓库，普通构建无需下载模型。本地离线验证文件由 `.gitignore` 排除。

```powershell
.\gradlew.bat :app:assembleDebug
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

`-PtargetAbi=arm64-v8a` 只打包单个 ABI，用于缩短本机安装调试的构建时间；省略时仍打包 `arm64-v8a` 和 `x86_64`。

跑与 PR、release 相同的校验：

```bash
./gradlew verify
```

这会运行所有模块的 host/unit 测试与依赖级 Android Lint，覆盖流水线、设置持久化、通知抽取与数据库迁移。

首次使用：

1. 在事件页点击「下载 / 继续下载模型」。下载约 679 MB 到应用私有目录，显示进度；网络失败后可重试并续传。
2. 授予「通知使用权」，确认页面显示「监听服务：已连接」。已授权但尚未连接时，可点击「重新连接」请求系统绑定。
3. 点击「开启降噪」。每次开启前校验全部模型的大小和 SHA-256，确认模型初始化成功、通知使用权存在且监听服务实际连接。
4. 点击「停止降噪」可立即停止通知及短信采集、拦截。系统监听服务仍由 Android 管理；页面区分系统连接状态和降噪运行状态。

> 部分 ROM 重装 APK 后通知监听仍显示已注册但实际未绑定，通知进不来。在系统设置里关掉再打开「通知使用权」即可恢复。

下载使用 Hugging Face HTTPS 地址，固定仓库 revision `058cbf34ed2c6a2854ec60e9534c229d08740387`，并校验固定 SHA-256。只有校验成功的完整文件才安装，未完成文件以 `.part` 保存。服务器不支持 Range 时重新下载当前文件。下载由 dataSync 前台服务执行，切换页面或退到后台继续下载，通知栏显示进度并提供暂停按钮。需允许通知权限才能在通知栏展示；拒绝后仍可在应用内看进度。系统回收服务后支持重投下载任务并续传，强行停止或重启手机后需手动继续。Android 的后台时间限制仍适用。首次下载需能访问 Hugging Face，失败原因会显示在页面和通知中。

「设置 → 网络代理」独立页面提供跟随系统 / VPN、直连、HTTP 和 SOCKS5（无认证）代理配置。当前应用联网仅用于模型下载，保存后在下次下载或继续下载时生效。电脑代理需允许局域网访问，填写电脑局域网 IP 和端口，不能填代表手机自身的 127.0.0.1。HTTP 代理通过 CONNECT 隧道下载 HTTPS 模型，模型校验不变。

开启状态保存在本机。重启后重新校验模型、初始化，只有系统监听重新连接后才恢复处理；模型缺失、损坏或监听断开时暂停，不拦截消息。新安装默认关闭。读取短信为可选权限，仍需用户授权。分类在下载完成后可以离线运行，当前构建包含 `arm64-v8a` 和 `x86_64` 原生库。

## 模型与准确率

Android 推理代码与模型来自 [Laya Multilingual LiteRT](https://huggingface.co/litert-community/Laya-Multilingual-LiteRT)，固定使用 256 token、FP16 权重存储和 CPU 推理。来源、许可与 host contract 保存在 `third_party/laya-litert/`。模型文件不纳入 Git。可选的本地验证文件存放于 `app/src/main/assets/laya/`，由 `.gitignore` 和构建配置排除；运行时模型保存在应用私有目录。

上游的 201 条英日文设备校验样本在 Android 模拟器上分类结果全部一致；新增的中文广告短信样张可完成推理并返回「广告」。这些结果只验证运行路径，不能代表中文短信和通知的准确率，也不能代表真机耗时。上线自动拦截前应使用标注的中文样本评估误拦率，并在目标手机上测延迟、内存及耗电。

主应用的通知链路已在 Android 37 x86_64 模拟器中验证：广告样张返回「广告」(97.39%) 并隔离、撤销通知；验证码由 OTP 闸门放行；中文配送通知返回「正常」并保留。分类门槛使用所选类别的概率，不使用 Laya 的整体熵置信度。当前输入为正文、标题和用户规则；不将应用名、渠道名、历史统计输入模型，避免来源元数据主导正文分类。固定窗口会截断过长的输入。

先前内置模型版本已通过模拟器离线分类和 51 项核心单元测试。在线下载版本增加下载及服务状态测试；应用清单包含用于模型下载的 `INTERNET` 权限。完整公网模型下载尚需在能访问 Hugging Face 的网络上验证。

## 行为要点

### 通知是在判断之后才被撤销的

Android 给 `onNotificationPosted` 的预算极短，判断只能放进协程，结论回来后再撤销。实际效果：

> 被拦截的通知会先在通知栏停留整个判断时长，然后消失。

这不是 bug，但也不是"拦截"通常暗示的那种效果。除非阻塞系统回调，否则没有办法在通知出现之前做出判断。

每个通知 key 有一个 generation：旧消息的判断结果无法撤销已被更新或重投的通知。模型任务最多 4 个并发，模型阶段 15 秒总时限（含排队与重试）。在飞的通知判断最多 64 条，超过即放行。

### 拦截短信只移除它的通知

只有默认短信应用能删除短信。JevNoiseGate 不是默认短信应用，也不打算成为——那意味着要接管每一条正常消息的投递，包括验证码。

所以拦截短信指的是撤销短信应用弹出的那条通知。短信**本体仍留在收件箱和会话列表里**。对最常见的场景（看一眼就能忽略的广告）这已经去掉了绝大部分打扰，但这确实是一个限制。

短信广播只做采集与本机判定，8 秒预算；模型判断跑在独立的持久 WorkManager 任务里。撤销请求最多等 60 秒等一条匹配的通知；匹配不明确或群发通知一律保留，以保护无关消息。

在有短信权限时，通知侧会等最多 1 秒，让唯一匹配的已采集短信认领这次判断（含待处理与已放行的记录）。采集缺失或匹配不明确时通知侧继续自行处理。这避免了关联消息的重复模型调用；格式异常或采集过迟仍会走通知侧兜底。

### 隔离与恢复

事件页有分页的隔离区视图。恢复会重新发一条 JevNoiseGate 通知，内容为保存的标题与正文，并为"相同完整内容 + 相同来源桶"写入一条本机放行纠错。它不会重建原应用的通知按钮与 PendingIntent。发恢复通知需要通知权限。静默拦截只留审计事件，不提供恢复入口。

事件插入上限 10,000 行。采集侧请求时，后台按最慢 5 分钟一次的频率清理 30 天前的事件。用户纠错不受清理影响。从 2、3 版升级到 5 版的数据库迁移保留既有历史。

诊断页展示最近 1,000 条 MODEL/FALLBACK 的模型阶段耗时，以及当前进程最近 256 个已完成样本的阶段拆分。端到端计时在提交判断或取消时结束；之后短信通知的匹配、系统实际撤销时间都不计入。跨设备重启后短信任务的调度耗时与原始起点不可得。

## 设置项

| 设置项 | 说明 |
|---|---|
| 类别门槛与动作 | 存覆盖值而非完整配置；答案空间由出厂类别唯一定义。空表示全部沿用出厂值。 |
| 用户偏好规则 | 自由文本，注入模型 state，是软约束。 |
| 短信号码黑名单 | 号码 / 前缀 / 后缀匹配，在模型之前求值。硬规则。 |
| 应用监听过滤 | 整个应用不采集。 |
| 网络代理 | 仅用于模型下载。跟随系统 / VPN、直连、HTTP、SOCKS5（无认证）。保存在下次下载或续传时生效。 |
| 日志等级 | `OFF` 去掉全部日志开销，默认 `INFO`。 |
| 开发者模式 | 显示诊断页「自测」工具，并让本应用自己的通知按普通通知处理，以便自测通知走完整链路。 |

## 项目结构

- `app/`：主界面、模型下载与校验、本地 Laya 后端和启动条件检查。
- `core/decision/`：分类输入、阈值和动作映射。
- `core/pipeline/`：验证码闸门、本机判定与失败放行。
- `core/dispatch/`：短信、通知共用的判断入口与记录。
- `feature/notification/`、`feature/sms/`：Android 采集入口。

当前版本支持本地用户规则和类别门槛调整；不会在手机上训练模型权重。用户纠错驱动的本地个性化只需在事件页恢复一条消息即可生效。
