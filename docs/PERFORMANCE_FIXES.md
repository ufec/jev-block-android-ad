## SQL 对照

本页为第一轮修复及 schema 4 的历史结果。当前 schema 5 的后续修改和探针输出见 [第二轮修复](PERFORMANCE_FIXES_ROUND2.md)；当前脚本默认测量 schema 5。

运行 [探针](performance/sql_probe.py) 读取实际 Room schema 与 DAO SQL。修复前为 HEAD `e55eb15` / schema 3，修复后为工作区 / schema 4。各查询取 20 次中位数，保存点回滚每次修改，使样本数量一致。数据是 1,000 或 10,000 条模拟事件，已有记录正文各 1 KiB，新增行正文为短字符串。

原始输出：[修复前](performance/sql_probe_before.json)、[修复后](performance/sql_probe_after.json)。下表使用 10,000 条样本：

| 工作 | 修复前 | 修复后 | 解释 |
|---|---:|---:|---|
| 入库 + 容量维护 | 81.8007 ms | 0.0994 ms | 全表 `NOT IN` 清理改为计数和删除超额 1 行；新索引写入成本已包含。 |
| 恢复最近拦截短信 | 3.8172 ms / 37,163 VM 步 | 0.0455 ms / 182 VM 步 | 使用 `(source, decidedAtMs)` 索引，避免全表扫描和临时排序。 |
| Top 渠道 | 18.2050 ms / 140,423 VM 步 | 5.6931 ms / 80,421 VM 步 | 扫描较窄的覆盖索引，避免按分组创建临时树；按计数排序仍需要临时树。 |
| 三项独立总览查询 | 53.9624 ms / 212,571 VM 步 | 9.2815 ms / 200,026 VM 步 | 修复前为动作、后端尝试、隔离数的中位数之和；当前共享总览一次取得这些值及总数，仍是聚合扫描。 |
| 隔离区后续游标页 | 原实现持续增大 LIMIT | 1.0863 ms / 3,480 VM 步 | 当前固定最多 101 行，时间和 ID 组合游标支持同时间戳。 |
| 数据库分配空间 | 14,307,328 bytes | 15,298,560 bytes | 当前模拟库约增加 6.9%，反映索引和元数据成本。 |

计数查询在此 SQLite 中仅 9 个 VM 步；年龄清理用时间索引，未过期时仅 13 步。旧 `prune()` 为对照保留在 DAO 中，生产代码不再调用。

这些是桌面内存 SQLite 的暖查询结果，不包含 Room 调度、手机存储、Binder 或网络，不应转述为手机提速倍数。新增索引并非免费；这里同时记录了入库成本和分配空间。

```powershell
python docs/performance/sql_probe.py --schema-version 3 --revision e55eb15 > docs/performance/sql_probe_before.json
python docs/performance/sql_probe.py > docs/performance/sql_probe_after.json
./gradlew verify :app:assembleDebug :app:assembleRelease --console=plain
```

## 行为边界与设备验收

最终执行 `verify :app:assembleDebug :app:assembleRelease` 成功，耗时 3 分 30 秒。27 个测试套件共 169 个测试，失败、错误、跳过均为 0。Android Lint 为 0 错误、26 条警告，涉及依赖版本提示、启动图标与多余的 SDK 版本条件；Release 的 R8 压缩也已完成。测试与 Lint 汇总见 [验证输出](performance/validation_results.json)。Debug 与未签名 Release APK 位于 `app/build/outputs/apk/`。

短信关联使用最近 60 秒内的精确正文候选，再核对唯一匹配；不同通知格式、超过等待窗口或缺失广播可能继续产生通知侧判断。1 秒等待也会增加未找到短信所有者时的通知处理时间。保持保守放行和合集保护，诊断计数区分成功关联和回退。

完整链路指标截至决策或撤销请求提交，不包含系统实际删除通知时间，也不包含短信决定之后等待匹配通知的时间。准备耗时与数据库耗时存在包含关系，不能直接相加。采样只覆盖当前进程的完成事件，取消/过载另计数；设备重启后 Worker 不显示无效的原入口和调度耗时。

设备验收建议集中在四种负载：DEBUG 日志突发超过 64 条；128 条待撤销短信且活动通知无法匹配；10,000 行库持续入库并翻隔离页；四个模型请求并发时更换已保存代理配置。用 Perfetto/StrictMode 核对主线程文件 IO 和冷标签 Binder 工作，用新诊断页观察峰值、阶段 P95、快照和客户端创建次数。
